# SafetyBot — запуск на Railway

1. Распакуйте архив. Создайте приватный GitHub-репозиторий SafetyBot.
2. Загрузите содержимое папки в корень репозитория: bot.py, requirements.txt, Dockerfile, railway.json и остальные файлы.
3. Railway → New Project → Deploy from GitHub repo → выберите репозиторий.
4. Откройте сервис → Variables → добавьте BOT_TOKEN со значением токена из BotFather. Примените изменения и запустите Deploy.
5. В логах должно появиться «Бот запускается: polling.». Это начало запуска, окончательная проверка — ответ на /start в Telegram и работа кнопок на двух языках.

Команда запуска: python bot.py. Сборка через Dockerfile.
База данных, Volume и публичный домен не нужны. Оставьте одну реплику, не включайте Serverless/автосон и не задавайте HTTP healthcheck.
Остановите другие запущенные копии того же бота у владельца: одновременный polling с одним токеном приводит к Conflict/getUpdates.
Токен храните только в Variables, не в GitHub или переписке. .env автоматически не загружается.

## Что изменено
Вместо ручного ввода токена используется BOT_TOKEN; добавлены файлы сборки и запуска. Информационные тексты и контакты сохранены из исходника. Их актуальность отдельно не проверялась; в исходнике указана необходимость редакционной и юридической проверки перед публичным запуском.

## Частые ошибки
- Не задан BOT_TOKEN: добавьте переменную в сервис Railway.
- InvalidToken / Unauthorized: проверьте токен у владельца через BotFather.
- Conflict / terminated by other getUpdates request: остановите вторую копию и оставьте одну реплику.
- Бот не отвечает: проверьте Deploy Logs и напишите /start именно боту, которому принадлежит токен.

Зависимость закреплена: python-telegram-bot 22.5, Python 3.12 в Docker.
